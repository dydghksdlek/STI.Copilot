# RAG 검색 평가 하니스

런북 **의미검색이 맞는 근거를 데려오는지**를 숫자로 측정한다. LLM은 안 거치고 검색만 채점하므로 빠르다(수 초~수십 초).

## 실행
```
powershell -ExecutionPolicy Bypass -File eval_runner.ps1
```
- 사전 조건: 앱에서 **전체 재임베딩**을 한 번 해서 `runbook.vec`(벡터)가 있어야 한다.
- 결과: 콘솔에 요약, 상세는 `eval_out.txt`.

## 지표 읽는 법
- **Recall@K** — 정답이 상위 K개 안에 든 질문 비율. `Recall@5=90%`면 "10개 중 9개는 상위 5위 안에 정답이 있다".
  - 근거 답변엔 **Recall@5**가 가장 실용적(상세 3~5건에 들어가야 하니까).
- **MRR** — 정답 순위의 역수 평균(1위=1.0, 2위=0.5…). 1에 가까울수록 정답이 위쪽에 정확히 꽂힘.

## 질문 추가/교체 (eval.json)
```json
{ "q": "사용자가 실제로 물을 법한 질문", "expected": ["rb-000123"] }
```
- **q**: 항목 제목과 **다른 표현**으로 써야 진짜 의미검색을 테스트함
  (예: "과열" 대신 "너무 뜨거워"). 구어체·오타·동의어일수록 좋음.
- **expected**: 그 질문에 나와야 하는 항목 id(여러 개 가능). 하나라도 상위 K에 들면 hit.
- 실제 런북·실제 질문으로 채울수록 평가가 현실을 반영한다.

## 언제 돌리나
컷오프·임베딩 모델·청킹 등을 바꿀 때마다 실행해 **점수가 오르는지**로 개선 여부를 판단한다.
"느낌"이 아니라 숫자로.
